# 地理王の画面を変えるときの手順

ユーザーは Android・iPhone の実機で確かめて、頼んでいない所が変わっていたり壊れていたりするとすぐ気づく。2026-09-24 だけで次の失敗があった。どれも「変えた所だけ見て、ほかを見なかった」のが原因。

- 「部屋の名前」を折り返さないための `.settings label>span{white-space:nowrap}` が、すぐ下の公開部屋の長い説明にも効き、ロビーの枠が画面から横にはみ出した（しかもユーザーが頼んだ変更ではなく、レビューで見つかった細かい問題を勝手に直したもの）
- アプリ内フレームを入れたら、フレームの中でも native.js が動いて「対戦へ戻る」が効かなくなった（音だけ鳴る）
- 見出しの潰れを「解消」とコミットしたのに、太い字体のままで潰れていた
- メディアクエリを基本のルールより前に書き、上書きされて効いていなかった

だから、見た目の変更は「頼まれた所が直ったか」と「それ以外が変わっていないか」の両方を、道具で確かめてから報告する。

## 1. 変える範囲を決める

- **頼まれた所だけ変える。** 作業中やレビューで別の見た目の問題に気づいても、その場で直さない。報告して、直すかどうかをユーザーに聞く。直してよいのは、頼まれた変更が原因で起きた問題と、頼まれた画面で明らかに壊れている所（はみ出し・文字が切れる等）だけ。
- 頼まれた内容があいまいなら（「小さくして」がどこを指すか等）、推測で広く変えず、いちばん狭い解釈で直して、その解釈を報告に書く。

## 2. 変える前に記録する

確認用サーバーを立てる（8080 番は別のセッションの古いサーバーのことがあるので使わない）。`.claude/launch.json` の `geoking-check`（PORT=8090, GEOKING_DEV=1）を `preview_start` で起動する。GEOKING_DEV=1 のときだけ `tests/` のスクリプトが `/dev/tests/` から読める（本番では出ない）。

ブラウザで http://localhost:8090/static/index.html を開き、**ファイルを編集する前に**:

```js
eval(await (await fetch('/dev/tests/layout_snapshot.js', { cache: 'no-store' })).text());
window.__r = null; layoutSnapshot('before').then(r => window.__r = r);
```

30秒ほどかかる（javascript_tool は45秒で切れるので、上のように裏で走らせて `window.__r` を待つ）。ホーム・ロビー・図鑑・クイズ・プライバシーポリシーを、幅 320/375/1024px・日本語/英語で、全要素の位置と大きさを記録する。

## 3. 変えるときの注意

- **CSS のセレクタを足したら、ほかに何に当たるか確かめる。** `label>span` や `.card p` のような広い書き方は、思わぬ要素に効く。足したセレクタを各ページで `document.querySelectorAll('…')` し、当たった要素が狙いどおりかを見る。できるだけ id や専用のクラスで狙う。
- **メディアクエリは、上書きしたい基本のルールより後ろに書く。** 書いたら `getComputedStyle` で値が本当に効いているかを見る。
- **見出しの字体（`--font-head` = Dela Gothic One）は画数の多い漢字が潰れる。** 小さめの見出しやボタンの漢字は `--font-body`（M PLUS 1p）の太字にする。
- **アプリ（Capacitor）は同じ Web ページを読み込んでいる。** 図鑑・クイズ・プライバシーポリシーはホームの上に重ねた iframe の中で開く。iframe の中では `env(safe-area-inset-*)` が 0 になり、native.js もフレームの中で動き、sessionStorage は外側と共有される。画面移動や native.js / sfx.js を触ったら、フレームの中と外の両方で考える。
- **対戦画面は、サーバーから状態が届くたびに `render()` で全部描き直す**（チャット1件、誰かのつなぎ直し、言語切り替え、ページの読み直しでも届く）。登場の動き・紙吹雪・音は「初めて見る内容のときだけ」出すこと。2026-09-24、結果の最中にチャットが届くと結果のめくる動きと紙吹雪がもう一度出て「結果が2回出る」と言われた（`revealKeyOf` / `geoking_revealed` で見せ済みを覚えて直した）。動きを足したら、その画面の最中にチャットを送る・`ws.close()` でつなぎ直す、を試す。
- 文言を変えたら日本語・英語の両方（i18n.js）を直し、長さが変わって折り返しやはみ出しが起きないかを見る。
- **「iPhone と Android で大きさが違う」と言われたら、まず画面の幅の違いを疑う。** ユーザーの Android は幅 約412px、iPhone は 390〜402px。`minmax(180px,1fr)` のような並びは幅 406px を境に1列↔2列が変わり、2026-09-25 には iPhone だけ結果の国旗が2倍の大きさになっていた。どちらも同じ WebKit/Blink の計算で、端末の違いではなかった。

## 4. 変えたあとに確かめる

ブラウザ（同じ http://localhost:8090/static/index.html）で、当てはまるものを全部流す。結果はそのまま報告に使う。

| 何を変えたか | 流すもの |
|---|---|
| 見た目・文言・HTML（いつも） | `layoutCompare('before')`（手順2の続き）と `tests/layout_check.js` |
| 色・背景・文字色（ダークモードも） | `tests/contrast_check.js`（ライトとダークの両方で。ダークは `resize_window` の `colorScheme:'dark'` にしてから） |
| 画面移動・native.js・sfx.js・図鑑/クイズ/プライバシーの開き方や戻り方 | `tests/app_frame_check.js` |
| server.py | `GEOKING_WS=ws://localhost:8090/ws python3 tests/e2e_two_players.py` と `tests/e2e_solo_bot.py`。部屋の中身・つなぎ直し・時計を触ったら `python3 tests/test_migration.py`（更新時の部屋の引っ越し）。切断・つなぎ直し・部屋を消すまでの猶予を触ったら `python3 tests/test_away_return.py`（別のアプリに行って戻る）。スプレッドシートに残す出来事（`sheet_log`）を触ったら `python3 tests/test_sheet_log.py` と `node tests/sheet_log_gs_test.js` |
| 結果（答え合わせ）画面のカード・国旗の大きさや並び | `tests/result_size_check.js`（幅ごとの列の数・国旗の大きさ・長い国名や数値のはみ出し）。iPhone（WebKit）はシミュレーターの Safari で `/dev/tests/result_size.html` を開く |
| 更新の自動読み直し（app.js の checkForUpdate・/api/version） | `tests/update_reload_check.js`（新しい版が見つかったとき、ホームで何もしていなければ読み直し、入力中・操作の直後・小窓や図鑑の枠・部屋にいる間は待つ）。アプリで確かめるなら、裏に回す → 版を変えてサーバーを立て直す（GEOKING_VERSION_SALT）→ 戻す |
| 観戦中の画面（みんなの手札・考え中/選択中/勝負の札） | `tests/spectator_check.js`（部屋を作って途中から観戦に入り、幅ごとに国旗の並びとはみ出しを見る）。iPhone は `/dev/tests/spectator.html` |

読み込み方（ほかのスクリプトも同じ）:

```js
window.__r = null; eval(await (await fetch('/dev/tests/layout_check.js', { cache: 'no-store' })).text()).then(r => window.__r = r);
// 数秒おきに window.__r を見る
```

見直しを別の担当（ワークフロー・サブエージェント）に頼んでいる間は、同じブラウザで確認を流さない。担当も同じブラウザの画面を使うので、ページを移動されたり表示の大きさを変えられたりして、確認が途中で切れる。担当には「ブラウザは使わない（使うなら新しいタブ）」と伝え、終わってから確認を流す。

確認中に「The page navigated while this script was running」と出たら、ファイルを書き換えた直後などにブラウザ側がページを読み直しただけのことがある。ページの状態を見てから流し直す（それでも毎回起きるなら、ページのコードを疑う）。

`layoutSnapshot` と `layoutCompare` は同じ条件で流す（ブラウザの表示の大きさを `resize_window` で変えたままにしない）。条件が違うと「【条件が違う】」と出て、変えていない画面まで変化として並ぶ。

`layoutCompare('before')` の読み方:
- 「大きさ・横位置が変わった」「増えた」「なくなった」の行が、**全部、頼まれた変更で説明できること**。説明できない行が1つでもあれば、意図しない変更が混ざっている。直してから流し直す。
- 「ページ幅 …（画面からはみ出している）」は必ず直す。
- 「縦にずれただけ」は、上の要素の高さが変わった影響なので、上の変更が頼まれたものなら問題ない。

そのうえで、変えた画面を目で見る:
- 375px と 320px のスクリーンショット、英語表示、必要ならダークモード。
- iPhone の見え方は iOS シミュレーターの Safari で `http://localhost:8090/static/index.html` を開けば WebKit で確かめられる（`mcp__Claude_Code_iOS_Simulator__control` の `open_url`）。

確かめた結果が1つでも NG なら「直りました」と言わない。直して最初から流し直す。

## 5. 報告とコミット

報告には次を書く（ユーザーは日本語で、専門用語は少なめに）。
1. 頼まれた変更で何が変わったか
2. それ以外に変わった所（`layoutCompare` で出たもの。なければ「ほかの画面は変わっていない」と、確かめた画面・幅・言語）
3. 流した確認と結果
4. 確かめられなかったこと（実機でしか分からない所）と、ユーザーに実機で見てほしい操作
5. 気づいたが直していない問題（直すか聞く）

コミットは自分が変えたファイルだけを名前を指定して add する。別のセッションが同じ作業ツリーを同時に編集・コミットしていることがあるので、`git status` / `git diff` で自分が書いていない変更が混ざっていないか見てから。デプロイは Render の Manual sync（ユーザーが行う）。アプリは Render のサイトを読み込むので、Web の変更だけならアプリの作り直しはいらない。

確認が終わったら確認用サーバーを止める。
